# PC 导航命中与用户故事动效

2026-09-13。仅修改 macOS。

## 导航修复

问题来自 plain Button 的透明留白没有明确的 interaction contentShape。旧版在 620pt 预览窗口中，点击「看板」行右侧留白 `(143, 113)` 后仍停留在记录页面。

主导航、设置导航和紧凑看板状态入口现在都在完整布局之后定义矩形点击范围。主导航行高 40pt，收起侧栏时也覆盖图标两侧；按压只缩放标签，外层命中矩形不缩小。选中背景只绘制，不参与命中，避免它在移动过程中干扰其他行。

原生坐标复测：
- 同一点 `(143, 113)` 成功切到看板。
- `(143, 167)` 的日历行留白成功切到日历。
- 收起侧栏后，图标外侧 `(51, 154)` 成功切到看板。
- 设置中 `(137, 175)` 的行留白成功切到外观。
- `⌘1` 仍直接切回记录。

## 动效叙事

| 用户故事 | 反馈与过渡 | 设定 |
| --- | --- | --- |
| 我准备点击一个入口 | 整行悬停高亮；按压标签轻微收缩 | hover 100ms，press 120ms |
| 我切换到另一个页面 | 侧栏选中背景移动，页面淡入淡出 | 160ms |
| 我展开侧栏或打开对话 | 布局平滑让出空间；对话从右侧轻移 12pt 出现 | spring response 0.26，damping 0.92 |
| 我新建或编辑记录 | 输入浮层从 0.98 比例淡入，原位编辑过渡 | 布局弹簧 / 160ms |
| 我完成一项任务 | 状态符号替换，列表项淡出并重排，列数量变化 | 120ms / 布局弹簧 |
| 我切换状态或日期 | 新状态 / 当天列表淡入，避免整页突变 | 160ms |
| 我等待 AI 结果 | 使用真实等待状态；新回复轻移 4pt 淡入 | 180ms，不使用打字机假进度 |
| 我保存或恢复内容 | 底部反馈轻移 6pt；恢复项从最近删除中移出 | 120ms / 布局弹簧 |

`NotoMotion.swift` 统一策略。弹簧的 response 是响应参数，不是固定结束时长；没有为了动画而延迟数据写入或禁用控件。连续输入由 SwiftUI 的状态动画重新定向。

## 键盘和辅助功能

本地事件监视器只记录输入来源类别，不记录键内容。键盘操作停用新增的自定义导航 / 布局动画；点击恢复指针动效。系统减少动态效果优先。异步回复可独立淡入，原生系统弹窗继续由 macOS 管理。屏幕边缘沿用已有的 Codenotch 展开逻辑。
