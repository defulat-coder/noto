# 待办药丸验收（2026-09-12）

把 [codenotch](https://github.com/vinzdg/codenotch) 的屏幕贴边交互移植到 noto：一枚黑色贴边凸舌，悬停展开「今日待办」环、「写一笔」和设置入口，再悬停到具体元素弹出带箭头的描述卡。窗口机制（非激活面板、⌥ 拖动贴边、光标监视、全屏检测）改编自 codenotch（MIT License，© vinzdg），见 `Sources/NotoApp/Pill/PillController.swift` 头部声明。

## 交互规范

- 凸舌是无边框、非激活的 `NSPanel`，`statusBar` 层级，`canJoinAllSpaces + stationary + fullScreenAuxiliary`：悬浮在所有窗口与 Space 之上，永不变成钥匙窗口、不抢焦点。
- **动效架构（防抖的关键）**：窗口尺寸恒定为最大展开态（322×264），位置只在启动、换边、⌥ 拖动、换屏时变化；悬停展开/收起是窗口内黑色剪影的 SwiftUI 形变，不做窗口 frame 动画。窗口级缩放动画的迟滞与重排是上一版抖动的根源。
- 沿边方向按「凸舌中点」锚定：展开只向屏幕内侧（across）和沿边下方生长，凸舌位置纹丝不动。
- 剪影为经典「刘海」造型：主体两端各有一片**内凹翼形曲线**张开、融进屏幕边框（三次贝塞尔：内侧竖直切线、贴边水平切线）；收起凸舌与展开主体共用同一形状按尺寸形变。
- 收起态：24×80 黑色凸舌，中间一道白色短线提示；展开态：72×264 黑色主体（两端翼形各占约 48）。
- 悬停凸舌即展开（接触即开，离开 0.5 秒后收起），内容沿边排列：
  - 「今日待办」环：进度 = 今日到期里未完成占比，颜色随负担绿→黄→红，环内是 checklist 图标，环下方为大号未完成数（对齐 codenotch 的「图标在环内、读数在环下」）；
  - 「写一笔」圆形按钮；
  - 底部设置齿轮（平时低亮度，悬停变亮）。
- 再悬停任一元素，向屏幕内侧滑出带尾巴的黑色描述卡，尾巴指向悬停元素：
  - 今日环 → 标题、进度条、「未完成 N / 已完成 M」、最多 3 条任务（逾期橙点）与溢出条数、「点击在看板查看」；
  - 写一笔 → 功能说明与「点击直接开始」；
  - 设置 → 功能说明与「点击打开设置」。
- 点击：环 → 打开主窗口并切到看板；写一笔 → 唤起主窗口录入框；设置 → 打开主窗口设置。药丸自身不做文本输入（非激活面板收不了键盘），录入走主窗口，保持永不抢焦点。
- 光标监视：全局 mouseMoved 监视器 + 0.3 秒轮询兜底（光标静止不产生事件）；`ignoresMouseEvents` 让面板除凸舌与描述卡外的区域完全透明，不挡底层点击。
- 右键菜单：打开主窗口、写一笔、贴边（左右上下）、隐藏待办药丸。
- 全屏应用在前台时药丸收起（CGWindowList 检测 + Space/激活通知 + 轮询兜底），退出全屏自动回来。**全屏判定只认「窗口完全覆盖整块屏幕」**：codenotch 原实现的第二判据（从菜单栏下方开始、贴到屏幕底）会把最大化但非全屏的普通应用误判成全屏，导致药丸在最大化应用前台永远隐藏，已收紧。
- 设置：`pillEnabled`（默认开）、`pillEdge`（默认右侧）在设置页。
- `--preview` 预览进程不创建药丸，避免干扰设计验收截图。

## 已知限制

- 点击动作、⌥ 拖动、右键菜单与全屏收起未纳入合成事件自动化（NSMenu/拖拽/点击激活在无头合成事件下不可驱动）；打开主窗口/录入框/隐藏的代码路径与已验收版本一致，全屏检测沿用 codenotch 已上线实现并收紧了判据。
- 药丸不做文本输入（见上）；主窗口关闭后（应用退出）药丸随之退出。
- 直接以可执行文件方式启动（绕过 LaunchServices）时，macOS 会推迟窗口合成且应用不激活；正常从 Finder/`open` 启动无此现象。
