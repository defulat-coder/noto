# Noto 数据与 AI 工作目录

更新：2026-09-13。目录通过 Foundation 系统 API 获取，下面为当前非沙盒 macOS 版本的典型位置。

| 内容 | 位置 | 生命周期 |
| --- | --- | --- |
| 笔记、任务、正式聊天历史、删除恢复数据 | `~/Library/Application Support/Noto/` 中的 SQLite 资料库 | 正式数据，不随缓存清理 |
| 账号隔离资料库与必要配置 | `Application Support/Noto/` 的既有账号目录 | 保持现有隔离与同步机制 |
| 界面偏好 | UserDefaults | 保持系统偏好存储 |
| AI 会话工作区及可重建快照 | `~/Library/Caches/Noto/AI/` | 可删除，下次请求重建 |
| 单次 AI 请求输入、stdout、stderr、结果文件 | 系统 `temporaryDirectory/Noto/AI/run-<UUID>/` | 正常完成、失败、取消时清理 |
| CLI 登录凭据 | 各工具原有位置 | 不修改 HOME 或全局登录配置 |
| 导出文件 | 用户选择的位置 | 由用户管理 |

## AI 会话缓存

```text
~/Library/Caches/Noto/AI/
  <资料库路径的 SHA-256>/
    <会话 ID 的 SHA-256>/
      conversation.json
      records.json
```

同一资料空间、同一会话复用目录，与所选 AI 工具无关。资料库路径不同即分开，避免本机与账号空间混用；哈希仅用于命名，不是加密。正式会话目录权限为 0700。

进程 cwd 使用上述固定目录；每轮运行文件在系统临时目录，与 cwd 分离。Claude Code、Codex、OpenCode 和 Kimi 共用这套规则。

`conversation.json` 保存此次请求提供的历史文本、当前问题及成功解析的回复；`records.json` 只保存此次选择的记录范围。两者都是可重建缓存，SQLite 是唯一的正式数据来源。打开会话从数据库读取，不能把缓存文件当成历史权威数据；缓存不存在时会自动创建，历史仍随请求直接传入。

提示词明确这是 Noto 对话工作区，不是软件项目，不要求用户先打开文档；缺少信息时只询问具体缺失项。原有工具限制和沙箱参数不变。固定 cwd 不代表第三方 CLI 的全部缓存和凭据也被迁移，也不构成额外文件系统安全沙箱。

## 旧位置迁移与删除

正式应用启动、CLI 发起 AI 请求时，将旧 `Application Support/Noto/AI` 下的数据移至 `Caches/Noto/AI`。不存在冲突时直接移动；已有缓存时合并目录，同名对话/记录快照保留缓存区版本，因为下一次请求会重建。未知同名文件不覆盖，保留在原处。空旧目录移除；此迁移不访问或改写正式 SQLite 文件。

删除任务成功后，移除该任务对应的会话缓存；远程删除实际落库后也清理对应缓存。数据库中的最近删除与对话恢复仍按原规则保留。缓存清理失败不回滚任务删除；恢复任务后不依赖旧缓存。别的会话中已选取过该任务的上下文快照不属于该任务自身缓存，不作全目录内容扫描。

预览和内存资料库使用系统临时目录下 `Noto-AI-Preview`，不写入正式缓存；CLI 无持续会话 ID 的单次请求使用独立目录。

若进程被强制终止，系统临时目录可能残留尚未清理的运行文件；不承诺崩溃时执行 defer。系统缓存可被清理，程序必须按缺失处理并重建。
