# Noto UI/UX 走查与优化建议

日期：2026-09-13。范围：当前工作区，包含最新任务录入精简。此次仅评审，不修改产品实现。

## 总体判断

连续玻璃、短操作栏、整行导航和按需展开已经形成一致方向。下一轮应优先解决操作后果、任务上下文与状态表达，再调整空间比例。继续机械地删标签可能把重要信息藏得太深。

## 走查步骤与证据边界

通过独立的 `--preview --compact` 实例查看示例数据，没有发送 AI 请求或修改真实任务。当前原生工具截图只在会话中显示，未导出可复查的图片文件，因此这是一份有现场视觉依据的部分走查记录，不是完整截图归档审计。

| 步骤 | 画面 / 行为 | 健康度与证据 |
| --- | --- | --- |
| 1 | 记录列表，完成 / 进行中 / 普通记录混排 | 基本清楚；现场截图看到已完成项仍标“今天到期”，元信息需要精确化 |
| 2 | 窄看板，待开始列与日期卡片 | 基本可用；现场截图看到绝对日期与记录页“明天到期”不一致 |
| 3 | 日历，月格与当日任务 | 层级可改善；现场截图中详情标题为 `2026-09-13 1`，日期与数字语义偏生硬 |
| 4 | 编辑已有重要 / 进行中任务 | 视觉简洁；现场截图与源码显示关闭和新建关闭语义不同 |
| 5 | 新建记录浮层 | 清楚；现场截图确认比任务录入紧凑，二者输入区高度策略不一致 |

## 建议，按价值排序

### P1 · 关闭编辑不应产生意料之外的数据丢失

关联：步骤 4、5；`TaskEditor.cancel`、`AppModel.cancelEditing`。

新建任务的 × / Esc 保留草稿，编辑任务的同一图形却立即取消修改。当前仅 help 文案能区分后果。原位记录使用“放弃修改”，反而更明确。

建议：无修改直接关闭；有修改时，使用清楚的“保存 / 放弃修改 / 继续编辑”分支，或实现可靠的编辑草稿恢复。不要为每次关闭都加确认，只处理确有修改的情况。

验收：输入、修改日期、重要或状态后关闭都走一致保护；键盘和鼠标行为相同，用户不丢输入。

### P1 · 空白草稿不应覆盖新的双击上下文

关联：步骤 3、4；源码 `quickCreateTask` 依据 `taskDraftStarted` 决定恢复，不判断用户是否实际输入或修改。

在某天打开空白新建后关闭，再双击另一日期，会继续沿用旧草稿日期；看板跨列也有同类风险。草稿保护方向正确，但用户没输入时，恢复旧属性容易让新任务创建到错误位置。此为代码路径确认，尚需补专门 UI 回归。

建议：区分“只打开过”和“用户实际修改过”。纯空白且未修改属性时采用新的日期 / 列；有真实草稿时恢复并轻提示“已恢复草稿”，保留旧上下文。

验收：跨日期、跨列、空白关闭、输入后关闭、自选属性后关闭各有明确结果。

### P1 · AI 对话需要显示实际使用的工具

关联：步骤 6；现场空会话只有“AI 对话”、记录摘要与内容范围。

设置中能看到四个品牌，但对话现场不知道请求将交给哪个工具，也看不出本机是否具备运行条件。工具缺失的反馈目前偏晚。

建议：在对话标题旁显示实际执行工具的小图标和名称；未找到可执行程序时给轻量状态及“前往设置”，避免等发送后才报错。显示实际请求的工具，不能用全局偏好冒充历史消息的工具。

验收：新会话、历史会话、修改偏好、未安装工具四种场景都不误导；不要声称检测到可执行文件就代表已登录。

### P2 · 同一任务的日期和完成状态统一表达

关联：步骤 1–3。

记录里“明天到期”，看板里 `2026-09-14`，日历详情里 `2026-09-13 1`。已完成任务仍显示“今天到期”，容易给人尚需处理的感觉。

建议：近期统一“今天 / 明天 / 9月16日”，跨年带年份，完整日期留在 help；日历详情用“今天 · 周日”加独立数量，而非裸数字。已完成项不继续显示紧迫式“到期 / 逾期”措辞。

验收：同一任务在三个页面的时间与状态含义一致，不依赖颜色推断。

### P2 · 任务输入按内容适度增长

关联：步骤 4、5。

新任务面板的简洁方向应保留，但任务短文本被放在较大的固定输入区域；记录浮层更紧凑。两者现在像两套不同的录入体验。

建议：统一小标题、正文、底部工具栏的对齐和动作位置。单行任务使用更紧凑的起始高度，多行输入增长到上限再滚动。允许记录实底与任务玻璃的材质差异，不必为了“一致”取消可读性设计。

验收：1 行、5 行、长粘贴、输入法组合输入均不跳焦点，底部动作不被推到窗口外。

### P2 · 空态和快捷录入的可发现性

关联：步骤 2、3；当前空态及双击逻辑源码。

双击是有效加速方式，但用户未必知道；只显示“暂无任务”不告诉用户可以在哪里开始。

建议：只在空列 / 空日期使用可操作的轻量“添加任务”入口，继承相同状态或日期。双击作为补充，不把操作说明常驻到每张卡片，也不在每列增加重复大按钮。

验收：首次用户不需要知道双击规则；空态点击、双击、⌘N 的默认属性符合场景。

### P2 · 边缘任务摘要与打开后的页面对应

关联：步骤 9，源码依据，未现场复测。

边缘“今日任务”实际包含逾期；点击后打开整个看板。任务环表达未完成比例，视觉上又容易被当作完成进度。

建议：先明确它表示“待处理”还是“今日”。保留未完成口径时改用更准确的命名，并让点击落到相应任务集合；若采用完成环，则同时调整分子、颜色和提示文案。不要只反转环形颜色。

验收：摘要数、列表条目与落地页面能对得上，无日期任务和逾期任务规则清晰。

### P3 · 设置和恢复保持稳定，收敛小差异

关联：步骤 7、8，源码依据。

设置不需要再整体改版。后续只应处理：短选择器的点击范围是否足够、原生菜单内部 inset 造成的视觉边缘差、最近删除与其他浮层的标题层级。账号配置中的数据去向说明不能当作冗余全部删掉。

建议：按实际屏幕检查后逐项微调；不要同时更换布局、材质和控件样式。恢复入口保留清楚的空间信息与操作结果。

## 无障碍与风险

现场看到辅助文字和日历任务数偏小、浅；玻璃背景会改变视觉对比，不能仅按一张截图宣布对比度达标。需要在明暗壁纸和减少透明度下测量。控件存在原生键盘名称与状态，这是良好基础；仍应验证焦点顺序、菜单返回焦点、任务完成按钮的点击范围，以及双击的单击 / 键盘替代入口。

## 建议实施顺序

1. 关闭保护、真实草稿识别：先减少操作失误。
2. AI 工具可见性、日期与完成状态：再减少理解成本。
3. 自适应输入高度、空态入口、边缘落地页：改善效率。
4. 最后做深浅色、文字对比和局部对齐复核，不重新推翻已稳定的设置布局。

本次没有实施以上建议，也未向真实 AI 服务发送数据。原生工具在设置走查阶段持续超时，因此没有将缺失页面描述为已完成视觉审查。

## 后续实施状态

已按用户授权落实：任务与记录编辑关闭保护、空白草稿上下文刷新、AI 工具名称/图标与本机检测、共享日期文案、内容自适应任务输入、空态添加入口、边缘到期待办筛选落地，以及最近删除标题收敛。原报告的“尚未实施”描述指评审当时状态；当前参数以 DESIGN-SPEC.md 为准。真实账号登录、AI 服务认证、全套深浅色/多显示器场景仍需独立验证。

本轮实施验证：64 项自动测试，1 项需真实服务的测试跳过、0 失败。隔离预览实测了任务短输入高度、日期相对文案、修改后关闭的三选项、继续编辑保留文字、放弃还原原任务、AI 标题工具图标。未发送真实 AI 请求或操作真实账号同步。
